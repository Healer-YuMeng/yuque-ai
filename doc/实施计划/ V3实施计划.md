## V3 功能扩展分模块开发方案（基于现有 V4 主链）

### Summary
在不破坏现有对话能力前提下，把后续扩展拆成 **5 个模块**，按 P0→P2 递进开发。  
核心目标是解决你当前痛点：**不再“首场景死锁单文档”**，而是“左侧锚点引导 + 上下文记忆 + 子树/同级检索 + 可回退可切换”。

---

### Key Changes（按模块与顺序）
1. **模块A：会话与状态内核（P0）**
   - 固化会话状态字段：`module_scope`、`catalog_anchor`、`has_collected_fields`、`trial_account_issued`、`scene_picked`。
   - 场景规则：新会话必须先选左侧；重进会话加载历史状态，不失忆。
   - 信息采集规则：姓名/单位/联系方式/感兴趣产品已收集的不再重复问。

2. **模块B：目录锚定与检索路由（P0）**
   - 左侧文档点击后作为“锚点输入”，**UI立即取消高亮**（按你确认）。
   - 锚点生效策略：持续到“重选文档或切换场景”，但检索不锁单文档。
   - 默认检索范围：**锚点文档子树 + 同级目录**（按你确认），未命中文档时可回退为上下文回答。
   - 修正 V4 流程：文本问题命中目录标题时可自动重锚；否则沿当前上下文。

3. **模块C：使用指南专属问答模式（P1）**
   - 当用户进入使用指南/已拿测试账号后，默认 `module_scope=使用指南`。
   - 回答策略：优先使用指南子树内容，支持步骤化操作讲解。
   - 引导策略：只在当前锚点相关目录内引导，不跨模块乱跳。

4. **模块D：留资与试用账号闭环（P1）**
   - “账号申请”按钮统一只弹窗，不自动插入对话消息（已对齐你当前要求）。
   - AI在使用指南类回答尾部可附带“是否需要测试账号”提示，并显示申请入口。
   - 若用户暂不需要账号：继续自然问答 + 按缺失字段渐进采集，避免重复采集。

5. **模块E：前端一致性与运维可控（P2）**
   - 四入口统一行为（5173 / 5173/visitor / 8000 / 8000/visitor）。
   - 场景/文档选中态视觉统一蓝系，且文档点击后不保留高亮。
   - 增加 TOC 刷新与 trace 可观测项（锚点、scope、检索范围、命中文档）。

---

### Test Plan
1. **锚点不死锁回归**
   - 先选“人工智能通识”，再选“跨学科项目式学习”，连续提问应切换到新目录内容。
   - 同一锚点下连续问不同问题，应在“子树+同级”内联动多文档，不重复单文档复述。

2. **会话记忆回归**
   - 留资字段收集后多轮对话不重复追问。
   - 已发放测试账号后刷新/重进会话仍保留状态，进入使用指南问答不失忆。

3. **入口一致性回归**
   - 5173 与 8000 的 visitor 行为一致：首轮禁输、先选场景、账号申请弹窗一致。
   - 新会话创建后左侧无默认场景选中，文档点击后立即去高亮。

4. **边界与降级**
   - 未识别到文档标题时，能基于历史上下文正常回答，不强制报错。
   - TOC 更新后刷新生效，不出现旧目录残留。

---

### Assumptions
- 所有新增能力继续挂在 **V4 主链**（`/chat/v4/stream`），不扩展 V3 旧旁路。
- 文档检索优先级采用：锚点子树 > 同级 > 上下文降级。
- 你要求的“开闭原则”在本轮按“尽量新增逻辑、最小化改动现有路径”执行；涉及当前 bug 修复处会做必要的小范围改动而非重构。
- 你提到的“必须通过 Context7 + 联网查最新文档”：实现阶段将以官方文档与现有依赖版本为准做校验；若运行环境无 Context7 可调用能力，将以官方站点检索替代并在交付记录中注明来源。
