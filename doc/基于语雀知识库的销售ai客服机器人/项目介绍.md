1) 项目定位（一句话）
这是一个语雀知识库驱动的企业 RAG 问答系统，后端用 FastAPI 提供检索/生成/会话 API，前端是 React 单页聊天界面，支持向量检索与 MCP 回退。

2) 技术栈（代码实锤）
后端：Python + FastAPI + Uvicorn + httpx + pydantic
检索：FAISS (faiss-cpu) + 向量嵌入（OpenAI 兼容）+ 语雀直连/MCP fallback
生成：openai SDK（兼容 DeepSeek/OpenAI 两类模型路由）
存储：SQLite（data_runtime/rag_mvp.db）+ 本地向量目录（data_runtime/vector_store）
前端：React 19 + TypeScript + Vite 8 + react-markdown
测试：pytest + pytest-asyncio
项目形态：Python 应用 + 独立 frontend 目录（不是 monorepo）
3) 目录与分层（你改代码时最重要）
API 层：app/api/chat_api.py（路由入口，含 /chat、/chat/stream、/docs/*、/mcp/*）
服务层：app/service/qa_service.py（核心编排，路由与 RAG 管线的桥）
RAG 层：app/rag/pipeline.py、app/rag/retriever.py、app/rag/generator.py
数据接入：app/data/yuque_loader.py、app/data/mcp_client.py
存储层：app/storage/vector_store.py、app/db/repositories.py、app/db/models.py
配置：app/core/config.py（.env 加载 + 全局 Settings）
前端主入口：frontend/src/App.tsx（当前几乎是单文件主逻辑）
4) 关键业务流（后续改功能先看这个）
启动：app/main.py 在 lifespan 初始化 QAService，注入 app.state.qa_service
聊天请求流：
前端调用 /chat/stream（SSE）
API 转发给 QAService.chat_stream
RAGPipeline.retrieve_context 先检索，再（可选）插图增强，再流式生成
检索策略（核心）：
有 embedder：向量检索优先，低命中再尝试 MCP
无 embedder：语雀直连检索，失败再 MCP
支持用户“@选中文档”锚定（selected_yuque_docs）
默认模式：
前端默认 chat_mode=visitor_sales，该模式下会有留资识别与会话管理逻辑
非 visitor_sales 场景才会进入 skill 路由（route_skill）
