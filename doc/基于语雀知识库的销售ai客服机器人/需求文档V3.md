一、项目基础现状
1. 技术架构&依赖
1. 无 LangChain、无 RAG 框架，纯调用语雀 Skill + MCP + 官方接口读取知识库。
2. Skill 能力约束：单次对话仅可命中 1 个 Skill，可用技能清单：
  - 过期检测、阅读笔记、碎片捕获、笔记润色、知识关联、风格提取、智能搜索回答、智能摘要（smart-summary，核心使用）
3. MCP 能力约束：单次请求可多次调用多个 MCP 工具，可用核心工具：
  - yuque_get_toc（获取完整目录树）、yuque_list_docs、yuque_get_doc（读取文档正文）、yuque_search（文档搜索）等。
4. 知识库结构：分为两大核心业务模块 + 独立功能模块
  - 主业务模块：平台介绍、案例分析（日常对话默认使用）
  - 独立模块：使用指南（仅用户明确提及才启用）
5. 交互入口：左侧场景按钮，对应「平台介绍」下二级目录：人工智能通识课程、跨学科项目式学习、智能招生、学校AI场景定制。
2. 核心业务规则（固定不变）
1. 对话身份：销售口吻，拟人化、耐心自然，输出内容精简，不堆砌大段文字。
2. 信息采集：每轮对话仅提问1项信息（姓名/单位/联系方式/感兴趣产品）；内置记忆机制，已采集信息不再重复询问。
3. 引导规则：每轮需引导用户继续提问，引导内容必须匹配语雀文档标题，保证 MCP 可正常检索。
4. 测试账号&使用指南联动规则
  - 触发1：用户开场直接要使用指南 → 立即推送指南内容，同步引导申请测试账号+常规信息采集。
  - 触发2：对话中主动询问「是否需要测试账号+使用指南」→ 用户同意后，补全剩余信息，信息全部收集完毕后统一下发测试账号+使用指南（对外不提及“信息采集/核对”等词汇）。
5. 模块切换规则
  - 常规对话默认使用「平台介绍、案例分析」模块文档。
  - 仅用户明确说出使用指南，临时切换至该模块匹配文档；对话结束/切换新场景后，自动切回「平台介绍」。
  - 用户重新点击左侧新场景，所有对话上下文、目录定位、模块状态全部重置，重新从「平台介绍」开始。

二、当前现存全部问题
问题1：同名文档标题冲突
不同模块/不同目录下存在标题相同、内容不同的文档；MCP 仅按标题检索，易匹配到错误文档。

问题2：单场景文档锁定，无法多文档联动
用户点击左侧场景后，全程仅命中该单篇文档；无法调用同目录下多篇关联文档，讲解内容单薄、逻辑断裂。

问题3：目录层级适配问题（新增核心问题）
1. 语雀 yuque_get_toc 可返回无限级树形目录（支持2/3/4/5级目录），但当前前端、AI 逻辑写死仅读取2~3级目录。
2. 知识库管理员新增4级及以上目录后，AI 引导、左侧菜单无法自动识别。
3. AI 引导无层级限制，易跨级、跨分支推荐目录，引导逻辑混乱。
4. MCP/前端存在目录缓存，语雀后台更新目录结构、文档后，系统不会自动加载最新目录。
问题4：信息采集节奏不合理
原逻辑曾计划多轮后再提问，不符合自然沟通要求；需改为首轮起每轮必带1个信息提问。

三、专项方案：多级目录平行引导（核心改造）
1. 基础说明
语雀 yuque_get_toc 返回完整无限级树形目录，通过 title、uuid、parent_uuid 关联层级，并非固定仅3级目录。
目录树示例：
[
  {
    "title": "平台介绍",
    "uuid": "xxx1",
    "parent_uuid": null,
    "children": [
      {
        "title": "人工智能通识课程",
        "uuid": "xxx2",
        "parent_uuid": "xxx1",
        "children": [
          { "title": "课程概述", "uuid": "xxx3", "parent_uuid": "xxx2" },
          { "title": "课程内容", "uuid": "xxx4", "parent_uuid": "xxx2" }
        ]
      },
      { "title": "跨学科项目式学习", "uuid": "xxx5", "parent_uuid": "xxx1" }
    ]
  }
]
现存根因：前端菜单、AI 引导逻辑硬编码层级，而非动态解析目录树。

2. 核心规则：同级目录引导（统一标准）
核心原则：AI 与前端菜单，仅展示/引导当前目录节点的直接子节点，不跨级、不跨分支，自动适配2~N级目录。
1. 初始定位：默认锚定一级节点「平台介绍」，引导其二级直接子节点。
2. 进入子节点：用户点击/选择某二级节点后，锚定当前节点，仅引导其三级直接子节点；以此类推，新增4/5级目录也可自动适配。
3. 回退规则：用户提出「返回上一级/更换模块」，节点切回父节点，重新展示父节点下所有同级子节点。
4. 场景重置：用户点击左侧新场景，目录锚点重置为「平台介绍」对应二级节点，层级从头开始。
3. 技术实现逻辑（伪代码+功能函数）
（1）每次对话强制拉取最新目录（解决缓存不更新问题）
# mcp_client.py 目录拉取逻辑，取消静态缓存，实时获取最新TOC
class YuqueMCPClient:
    def get_latest_toc(self):
        # 每次对话/点击场景，重新调用MCP获取完整目录树
        toc_tree = self.call_mcp_tool("yuque_get_toc")
        return toc_tree

（2）定义核心工具函数：获取当前节点的直接子节点
def get_direct_children(current_node):
    """仅返回当前节点的下一级直接子节点，不限目录级数"""
    return current_node.get("children", [])

（3）目录节点定位&流转逻辑
# 1. 初始化：加载完整目录树 + 锚定初始节点
toc_tree = mcp.get_latest_toc()
current_node = find_node_by_title(toc_tree, "平台介绍")

# 2. 获取同级子节点，用于前端渲染 + AI引导
sibling_list = get_direct_children(current_node)

# 3. 用户选择某一子节点后，更新当前锚点，进入下一级
selected_node = 选中的目录节点
current_node = selected_node
# 下一轮继续获取该节点的直接子节点，循环执行

（4）前端菜单改造
左侧场景按钮不再硬编码，每次加载对话/切换节点时，从「当前节点的直接子节点」动态渲染按钮，与 AI 引导内容保持一致。

4. 结合同名文档的兼容处理
1. 检索过滤：搜索文档时，携带当前节点 uuid + 所属模块名称双重过滤。
2. 标题标识（可选优化）：语雀文档标题增加模块前缀，例：【平台介绍】人工智能通识课程、【使用指南】人工智能通识课程，从源头区分同名文档。

四、整体对话全流程逻辑（整合所有业务规则）
通用单轮对话固定结构（所有场景通用）
多文档讲解内容（智能摘要输出） + 1项信息提问（不重复） + 同级目录引导语

流程1：用户首次点击左侧场景（默认平台介绍模块）
1. MCP 调用：yuque_get_toc（最新目录）→ yuque_search 匹配当前场景 → yuque_get_doc 拉取多篇同级关联文档。
2. Skill 调用：使用 smart-summary 对多篇文档生成精简摘要。
3. AI 输出：摘要讲解 + 首个信息提问 + 引导当前节点的直接子节点。
4. 目录锚点：锁定用户点击的二级节点。
流程2：常规多轮对话（循环流转）
1. 读取历史记忆，跳过已采集的信息项。
2. MCP 拉取当前目录节点下多篇子文档，Skill 摘要整合。
3. AI 输出：内容讲解 + 下一项未采集信息提问 + 同级目录引导。
4. 全程遵循：不跨级引导、不重复提问、内容精简。
流程3：用户提及/索要「使用指南」
1. 临时切换匹配模块为「使用指南」，调用对应目录&文档。
2. 若用户直接索要指南：立即推送指南摘要内容 → 信息提问 + 引导测试账号。
3. 若对话中询问指南：解答后自动切回「平台介绍」模块，继续原有流程。
4. 用户同意领取测试账号+指南：完成剩余信息采集后，统一下发账号+指南（无敏感话术）。
流程4：用户切换新场景
1. 重置所有状态：目录锚点、模块定位、引导内容。
2. 重新加载最新目录树，回归「平台介绍」二级节点，从头开始对话流程。

六、核心总结
1. 语雀 MCP 的 yuque_get_toc 原生支持无限级目录，目录层级不足是代码硬编码+缓存导致，非接口限制。
2. 目录引导统一规则：锚定当前节点，只引导直接子节点，自动适配2~N级目录，不跨级、不跨分支。
3. 所有对话、检索、菜单均基于实时最新目录树，保证知识库更新后前端、AI 同步生效。
4. 业务逻辑闭环：多文档讲解 + 逐轮信息采集 + 同级目录引导 + 指南/测试账号联动，完全贴合销售场景需求。
