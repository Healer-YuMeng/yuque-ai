## 0. 前置说明

### 0.1 本文边界

本文只描述 V5 后端重构与必要前端联调契约，不直接修改任何源码。后续进入开发阶段时，应以本文为实施准入文档，由维护者确认后再写代码。

V5 的核心目标是新增一条「知心朋友小为」独立链路：

- 以联网搜索为主信息源，持续提供更实时的产品介绍与案例信息。
- 语雀知识库只作为补充链接来源，不把语雀全文注入 V5 prompt。
- 不沿用 V4 的销售顾问、目录状态机、Skill 规划、留资引导和试用账号链路。
- 保留现有 V1/V2/V3/V4 能力，不改变既有接口语义。

### 0.2 关于「只新增代码，不修改代码」

如果严格理解为「只能新建文件，不能改任何已有文件」，则 V5 可以开发出可导入的模块和测试，但无法让 FastAPI 暴露 `POST /chat/v5/stream`，也无法让前端实际调用到 V5。原因是当前应用入口只在 `app/main.py` 中注册了 `app.api.chat_api` 的 router，现有 `ChatRequest.chat_mode` 也只允许 `"visitor_sales"` 与 `"rag"`。

建议将该约束落为：

- **新增为主**：V5 业务逻辑、人设、标签解析、编排器、测试均创建新文件。
- **最小接入**：只在必要接入点新增代码行，不改写现有 V4/V3/V2/V1 逻辑。
- **可回滚**：V5 通过 `CHAT_V5_ENABLED=false` 默认关闭；关闭时新接口返回明确 503，不影响旧接口。

已人工确认：允许在 `app/main.py`、`app/core/config.py`、`app/schemas/chat.py`、`app/api/chat_api.py` 或等价接入文件中追加少量 V5 接入代码；仍要求新增为主、最小接入、可回滚。

### 0.3 官方文档核对结论

本次环境未暴露可调用的 Context7 工具，已改用官方文档与本地接口文档核对。核对日期为 2026-06-04。

| 主题 | 官方依据 | 对 V5 的影响 |
|------|----------|--------------|
| 阿里云百炼联网搜索 | [阿里云百炼：联网搜索](https://help.aliyun.com/zh/model-studio/web-search/) | OpenAI 兼容 Chat Completions 可通过 Python SDK 的 `extra_body={"enable_search": True}` 启用联网搜索；部分新模型在文档中标注为 Responses API 支持，需要做模型能力判断。 |
| FastAPI SSE | [FastAPI Server-Sent Events](https://fastapi.tiangolo.com/tutorial/server-sent-events/) | 官方推荐 SSE 使用 `text/event-stream`；当前仓库已用 `StreamingResponse` 手写 SSE 事件，V5 应沿用既有实现风格，避免引入新依赖。 |
| 语雀生态 | [语雀 GitHub 官方组织](https://github.com/yuque)、[Yuque AI Ecosystem](https://yuque.github.io/yuque-ecosystem/) | 语雀官方生态包含 `yuque-mcp-server` 与 OpenAPI Spec；当前仓库已有 `YuqueMCPClient` 和本地 OpenAPI HTML，可继续复用只读检索能力。 |
| 语雀 OpenAPI V2 | [yuque_openapi_20251121_green.html](../../yuque_openapi_20251121_green.html) | 可用接口包括通用搜索、文档详情、文档列表、目录等；V5 只需要文档标题/URL，不需要拉全文参与生成。 |

**已确认决策**：V5 默认模型固定为 `qwen3.7-plus`，并且前端需要拿到联网搜索的具体来源内容。阿里云/千问联网搜索文档显示，返回搜索来源需要启用来源返回能力，例如 `enable_source=true` 后读取 `search_info.search_results`。因此 V5 默认链路不能只做「普通 Chat Completions + answer 文本」，而应新增一个支持搜索来源回传的 V5 专用搜索生成适配器：

1. 默认模型：`CHAT_V5_MODEL=qwen3.7-plus`。
2. 默认要求：联网搜索结果来源必须进入 SSE `done.sources`，其中 `source_type="web"`。
3. 适配器策略：优先使用 `qwen3.7-plus` 官方支持的百炼/千问联网搜索协议；若当前 SDK/协议不能返回 `search_info.search_results`，必须在 V5 generator 层显式报错或降级到可返回来源的 DashScope 协议，不允许静默只返回回答正文。
4. 兼容策略：`qwen-plus` 等 Chat Completions 兼容模型可作为备用，但不是 V5 默认模型。

## 1. 现有基线

### 1.1 后端入口

当前主应用为 `app/main.py`：

- 创建 `FastAPI(title=settings.app_name, lifespan=lifespan)`。
- 在生命周期中初始化 `QAService`、`YuqueLoader`、SQLite repositories、`VectorStore`。
- 通过 `app.include_router(chat_router)` 注册 `app/api/chat_api.py` 中的所有 HTTP 路由。
- 若存在 `frontend/dist`，由 FastAPI 托管 React 构建产物。

### 1.2 现有聊天链路

| 链路 | HTTP | 主要服务 | 状态 |
|------|------|----------|------|
| V1 RAG | `POST /chat/stream` | `QAService.chat_stream()` | 保留 |
| V2 多媒体 | `POST /chat/v2/stream` | `QAService.chat_v2_stream()` | 保留 |
| V3 画像推荐 | `POST /chat/v3/stream` | `QAService.chat_v3_stream()` | 保留 |
| V4 销售目录状态机 | `POST /chat/v4/stream` | `QAService.chat_v4_stream()` + `SalesDialogOrchestratorV4` | 保留 |
| V5 知心朋友 | `POST /chat/v5/stream` | `FriendDialogOrchestratorV5` | 新增 |

### 1.3 关键限制

现有 `app/schemas/chat.py` 中：

```python
chat_mode: Literal["visitor_sales", "rag"] = "visitor_sales"
```

这意味着请求体中传入 `chat_mode="friend_v5"` 会被 Pydantic 拒绝并返回 422。V5 要上线，必须新增 V5 专用 request model，或扩展现有 `chat_mode` Literal。

现有 `ChatSessionRepository.list_recent_messages()` 以 `session_id` 查询历史，V5 必须避免复用 V4 session。最稳妥做法是：

- 前端生成 V5 session 时使用 `sess_v5_` 前缀。
- 后端 `ChatV5Request` 校验 `session_id` 前缀。
- V5 服务层只读取当前 `session_id` 的历史，不使用 V4 的 `visitor_sales` session。

## 2. V5 总体架构

### 2.1 架构原则

1. **旁路新增**：V5 与 V4 平行存在，不复用 V4 编排器，不在 V4 代码里叠分支。
2. **联网优先**：每轮主生成都启用联网搜索；语雀只作为链接补充。
3. **语雀轻量化**：语雀检索只返回 `title/url/snippet/doc_id`，不调用 `get_doc()` 拉全文给 LLM。
4. **小画像**：只收集 `display_name` 与 `org_name`，不主动采集联系方式。
5. **目录标签驱动**：每轮回答完成后返回 3 个推荐标签，标签必须来自当前语雀目录节点，前端点击后作为下一轮输入。
6. **刷新即新会话**：用户每次刷新 V5 页面时，前端强制重新拉取语雀目录，并进入新的 `sess_v5_` 对话页面。
6. **默认关闭**：通过 `CHAT_V5_ENABLED` 控制，确保上线前不影响现有功能。

### 2.2 运行时数据流

```text
前端选择场景 / 点击标签 / 输入问题
        │
        ▼
POST /chat/v5/stream
        │
        ▼
ChatV5Request 校验
  - chat_mode == "friend_v5"
  - session_id 以 sess_v5_ 开头
  - scene 属于四个场景之一
        │
        ▼
QAService.chat_v5_stream()
        │
        ├─ ensure_session(session_id, chat_mode="friend_v5")
        ├─ list_recent_messages(session_id, limit=20)
        ├─ append_message(role="user")
        │
        ▼
FriendDialogOrchestratorV5.answer_stream()
        │
        ├─ ProfileExtractor.extract_update()
        ├─ 只保存 display_name / org_name / interests
        ├─ Yuque URL lookup（可选，只取链接）
        ├─ FriendV5Generator.stream()
        │    └─ qwen3.7-plus 联网搜索适配器
        │       enable_search=true, enable_source=true
        │       → token + web_sources
        ├─ TagsBlockParser 剥离 [TAGS] 块
        ├─ 用 question / scene / [TAGS] 线索匹配语雀目录节点
        └─ 输出 SSE token / done / error
        │
        ▼
前端渲染回答 + TagChips
```

## 3. HTTP 与 SSE 契约

### 3.1 Endpoint

```http
POST /chat/v5/stream
Content-Type: application/json
Accept: text/event-stream
```

### 3.2 Request

```json
{
  "chat_mode": "friend_v5",
  "question": "人工智能通识教育",
  "session_id": "sess_v5_4f2c4a8e",
  "scene": "人工智能通识教育",
  "trigger_type": "scene",
  "model": "qwen3.7-plus",
  "owner": "",
  "token_profile": "primary"
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| `chat_mode` | 是 | 固定为 `friend_v5`。 |
| `question` | 是 | 用户输入、场景名称或点击标签文本。 |
| `session_id` | 是 | 必须以 `sess_v5_` 开头，防止串到 V4 历史。 |
| `scene` | 是 | 四个场景之一：人工智能通识教育、智能招生、跨学科项目化学习、学校AI场景定制。 |
| `trigger_type` | 是 | `scene`、`tag`、`manual`。用于判断是否执行语雀 URL lookup 与首轮策略。 |
| `model` | 否 | V5 使用的模型；为空时用 `CHAT_V5_MODEL`，再回落到 `LLM_MODEL`。 |
| `owner` | 否 | 语雀 scope 动态路由，沿用现有模式。 |
| `token_profile` | 否 | `primary` 或 `secondary`，沿用现有语雀 Token 档位。 |

`history` 不建议由前端作为权威传入。V5 后端应优先使用服务端 `session_id` 历史，避免用户或前端状态污染 prompt。如需兼容产品文档中的 `history` 字段，可以在 `ChatV5Request` 中允许 `client_history`，但只取最近 6 条并做长度限制。

### 3.3 SSE events

V5 沿用当前仓库的事件格式：

```text
event: token
data: {"token":"..."}

event: done
data: {"answer":"...","tags":["..."],"sources":[...],"profile_fields":{"display_name":"...","org_name":"..."}}
```

#### `stage`

用于前端展示进度，可选但建议保留：

```text
event: stage
data: {"stage":"searching","detail":"小为正在结合联网搜索梳理资料..."}
```

建议 stage：

| stage | detail |
|-------|--------|
| `profile` | 正在整理本轮上下文... |
| `yuque_links` | 正在查找可补充阅读的语雀文档... |
| `searching` | 小为正在结合联网搜索梳理资料... |
| `generating` | 正在生成回答... |

#### `done`

```json
{
  "answer": "完整回答正文，不含 [TAGS] 块",
  "tags": [
    "想看看乐高人工智能课程怎么上课？",
    "要不要了解腾讯青少年 AI 课程？",
    "想看这类课程适合哪些年级？"
  ],
  "sources": [
    {
      "title": "人工智能教育进入中小学课堂的相关报道",
      "url": "https://example.com/news",
      "source_type": "web",
      "snippet": "联网搜索返回的标题、摘要或片段",
      "index": 1
    },
    {
      "title": "乐高人工智能课程介绍",
      "url": "https://www.yuque.com/...",
      "source_type": "yuque",
      "snippet": "可补充阅读的语雀文档"
    }
  ],
  "profile_fields": {
    "display_name": "赵老师",
    "org_name": "育才中学"
  },
  "fallback_used": false,
  "debug": {
    "pipeline": "friend_v5",
    "search_enabled": true,
    "web_source_count": 1,
    "yuque_lookup_used": true
  }
}
```

`sources` 必须支持两类来源：

| source_type | 来源 | 返回时机 | 用途 |
|-------------|------|----------|------|
| `web` | 百炼/千问联网搜索 `search_info.search_results` 或等价结构 | 每轮 V5 生成后，只要模型返回搜索来源就透传 | 前端展示联网搜索标题、链接、摘要/片段，支撑信息可追溯。 |
| `yuque` | `yuque_search` / `YuqueLoader.search_docs()` | 标签点击或具体文档问题命中后 | 给用户补充阅读入口；默认不把正文注入 prompt。 |

由于已确认前端需要联网搜索具体来源，若模型没有返回联网搜索来源，V5 后端应在 `debug.web_sources_missing=true` 标记，并在 `CHAT_V5_REQUIRE_WEB_SOURCES=true` 时返回 `error`，不要假装已经完成联网溯源。

#### `error`

沿用当前错误风格：

```text
event: error
data: {"message":"V5 链路未开启，请先设置 CHAT_V5_ENABLED=true。"}
```

## 4. 核心模块设计

### 4.1 `friend_persona_v5.py`

职责：

- 输出 V5 system prompt。
- 管理四个场景的说明。
- 管理禁用销售词。
- 管理标签格式约束。

建议接口：

```python
FRIEND_V5_SCENES = (
    "人工智能通识教育",
    "智能招生",
    "跨学科项目化学习",
    "学校AI场景定制",
)

FRIEND_V5_FORBIDDEN_TERMS = (
    "顾问",
    "销售",
    "留资",
    "线索",
    "试用账号",
    "申请测试",
)

def build_friend_persona_template() -> str:
    ...
```

V5 prompt 必须明确：

- 自称「小为」，不是「小为顾问」。
- 不主动索要联系方式。
- 每轮最多自然询问一个画像字段。
- 先承接用户，再给判断和建议；语气要热情、放松、有陪伴感，像一个愿意陪用户一起看资料、帮用户少走弯路的朋友。
- 允许轻微情绪和主动判断，例如「来，我先帮你拆开看」「这块其实不用一上来就看一堆清单」「如果是第一次了解，我会建议先看最容易落地的方向」。
- 避免客服式、百科式、销售式表达；不要把回答写成冷冰冰的产品说明、目录摘要或招商话术。
- 少用「课程定位 / 适合对象 / 落地价值」这类板正小标题；优先用用户能感受到的表达，例如「孩子更容易进入状态」「老师组织起来更顺」「适合做第一站」。
- 标签用 `[TAGS]` 与 `[END_TAGS]` 包裹，每行一个。
- 不向用户暴露 RAG、MCP、语雀、prompt、系统提示词等内部实现。

### 4.2 `chat_v5.py`

建议新建独立 schema 文件，减少对现有 `ChatRequest` 的侵入。

```python
class ChatV5Request(BaseModel):
    question: str = Field(..., min_length=1, max_length=2000)
    chat_mode: Literal["friend_v5"] = "friend_v5"
    session_id: str = Field(..., min_length=9, max_length=120)
    scene: Literal[
        "人工智能通识教育",
        "智能招生",
        "跨学科项目化学习",
        "学校AI场景定制",
    ]
    trigger_type: Literal["scene", "tag", "manual"] = "manual"
    model: Optional[str] = Field(default=None, min_length=1, max_length=120)
    owner: Optional[str] = Field(default=None, min_length=1, max_length=120)
    token_profile: Optional[str] = Field(default=None, max_length=24)

    @field_validator("session_id")
    @classmethod
    def _validate_v5_session(cls, value: str) -> str:
        sid = (value or "").strip()
        if not sid.startswith("sess_v5_"):
            raise ValueError("V5 session_id 必须以 sess_v5_ 开头")
        return sid
```

建议不要继承 `ChatRequest`，因为继承会受现有 `chat_mode` Literal 限制。

### 4.3 `friend_v5_generator.py`

职责：

- 基于 `settings.resolve_model_endpoint(model)` 找到 API key 与 base URL。
- 默认服务 `qwen3.7-plus`，优先使用支持返回搜索来源的百炼/千问联网搜索协议。
- 启用联网搜索与来源返回：至少包含 `enable_search=true` 与 `enable_source=true` 或等价参数。
- 从模型响应中提取 `search_info.search_results` 或等价结构，转换为 `source_type="web"` 的前端 sources。
- 对模型能力做显式校验；若当前协议无法返回搜索来源，必须报错或切换到可返回来源的协议，不允许只返回回答正文。

建议接口：

```python
class FriendV5Generator:
    def __init__(self, *, model: str, api_key: str, base_url: str) -> None:
        ...

    async def stream(
        self,
        *,
        system: str,
        prompt: str,
        search_strategy: str = "turbo",
    ) -> AsyncIterator[FriendV5StreamEvent]:
        ...
```

V5 搜索请求必须同时开启联网搜索和来源返回。若使用 OpenAI 兼容 Chat Completions，参数建议：

```python
extra_body = {
    "enable_search": True,
    "enable_source": True,
}
if search_strategy in {"turbo", "max", "agent"}:
    extra_body["search_options"] = {"search_strategy": search_strategy}
```

若 `qwen3.7-plus` 在当前区域/SDK 只支持 Responses API 或 DashScope 原生协议返回来源，则新增 V5 专用 adapter，不要把它塞进现有 `DeepSeekGenerator.stream_generate()`。adapter 输出事件建议：

```python
@dataclass(frozen=True)
class FriendV5StreamEvent:
    event: Literal["token", "web_sources"]
    token: str = ""
    web_sources: list[FriendV5SourceItem] = field(default_factory=list)
```

其中 `web_sources` 从 `search_info.search_results` 或等价结构转换，至少包含 `title`、`url`、`snippet`、`index`。

对 Qwen 模型可继续沿用当前仓库习惯加入：

```python
extra_body["enable_thinking"] = False
```

但要注意 `extra_body` 不应覆盖 `enable_search` / `enable_source`。建议用 helper 合并：

```python
def _merge_extra_body(*items: dict[str, Any]) -> dict[str, Any]:
    merged: dict[str, Any] = {}
    for item in items:
        merged.update(item)
    return merged
```

### 4.4 模型能力策略

新增配置建议：

```text
CHAT_V5_ENABLED=false
CHAT_V5_MODEL=qwen3.7-plus
CHAT_V5_SEARCH_STRATEGY=turbo
CHAT_V5_MAX_TOKENS=900
CHAT_V5_YUQUE_URL_LIMIT=3
CHAT_V5_STRICT_MODEL_CAPABILITY=true
CHAT_V5_REQUIRE_WEB_SOURCES=true
```

模型策略：

| 模型 | 建议处理 |
|------|----------|
| `qwen3.7-plus` | **V5 默认模型**。必须走可返回联网搜索来源的百炼/千问协议；sources 缺失时按 `CHAT_V5_REQUIRE_WEB_SOURCES` 报错。 |
| `qwen3.7-max` | 与 `qwen3.7-plus` 同类处理，需先做集成验证。 |
| `qwen-plus`、`qwen-max`、`qwen-flash` | 可作为备用模型；若 Chat Completions 能返回 `search_info.search_results`，可复用 V5 adapter。 |
| `qwen3-max` | 官方 Chat 示例使用过；仍建议做集成测试确认来源字段。 |
| `deepseek-*` | 阿里云文档列出部分 DeepSeek 模型支持联网搜索，但当前仓库可能直连 DeepSeek 官方 base URL，不能假设 `enable_search` 生效。 |
| `gpt-*` | 不应传阿里云私有 `enable_search`；若未来接 OpenAI web search，应另建 OpenAI Responses/Tools 适配器。 |

### 4.5 `friend_v5_tags.py`

V5 需要从流式输出里剥离标签块。如果直接把 LLM chunk 原样转发，`[TAGS]` 可能会短暂显示在前端。建议实现一个小型流式解析器：

```text
输入 chunk: "正文...\n[TAG"
暂存尾部，不立即输出

输入 chunk: "S]\n想看课程..."
识别 [TAGS]，停止向 token event 输出标签块

结束时:
  answer = 标签块前正文
  tags = 标签块内 3 行
```

解析规则：

- 标签块起始标记：`[TAGS]`
- 标签块结束标记：`[END_TAGS]`
- 只取非空行，去掉 `-`、序号和多余空白。
- 解析出的标签只作为目录匹配线索，不直接返回前端。
- 最终 `done.tags` 必须由 `FriendDialogOrchestratorV5` 从语雀目录节点标题中挑选。
- 若模型未输出标签或少于 3 个，使用 question / scene 在语雀目录中匹配并补齐。

目录标签匹配示例：

```python
TOC_TAGS_BY_SCENE = {
    "人工智能通识教育": [
        "乐高人工智能课程介绍",
        "课堂流程与作品展示",
        "适合年级与课时安排",
    ],
    ...
}
```

### 4.6 `friend_dialog_orchestrator_v5.py`

职责：

1. 读取当前 session 画像。
2. 调用 `ProfileExtractor.extract_update()`。
3. 只保存 V5 允许的字段。
4. 构建 V5 prompt。
5. 可选查语雀链接。
6. 调用 V5 generator。
7. 输出 SSE events。

关键约束：

- 不实例化 `SalesDialogOrchestratorV4`。
- 不实例化 `V4LeadOutreach`。
- 不调用 `CatalogStateMachine`。
- 不调用 `plan_sales_skills()`。
- 不调用 `retriever.retrieve()`。
- 不把语雀文档全文放入 prompt。

建议方法：

```python
class FriendDialogOrchestratorV5:
    async def answer_stream(
        self,
        *,
        question: str,
        session_id: str,
        scene: str,
        trigger_type: str,
        history: Sequence[ChatMessageRow],
    ) -> AsyncIterator[dict[str, Any]]:
        ...
```

### 4.7 V5 prompt 结构

```text
【角色】
<build_friend_persona_template()>

【当前场景】
人工智能通识教育

【已了解的信息】
- 称呼：赵老师
- 单位：育才中学

【本轮输入】
用户通过标签/手动输入问：乐高人工智能课程

【可补充阅读的语雀链接】
- 乐高人工智能课程介绍：https://www.yuque.com/...

【输出要求】
1. 使用自然中文回答，像朋友聊天。
2. 联网搜索优先，结合搜索结果给出判断。
3. 如有语雀链接，只作为“想进一步看原文可参考”。
4. 不主动索要联系方式。
5. 最后输出：
[TAGS]
...
[END_TAGS]
```

### 4.8 语雀 URL lookup

V5 的语雀策略是「只取链接」。推荐顺序：

1. 首选 `YuqueMCPClient.search(query)`，因为当前 MCP client 已做只读工具白名单和 scope 过滤。
2. MCP 不可用时，使用 `YuqueLoader.search_docs(query)`。
3. 只保留 URL、标题、摘要，不拉取正文。
4. 如果没有 URL，不编造，不返回。
5. 每轮最多返回 3 条。

触发建议：

| trigger_type | 是否查语雀 URL | 说明 |
|--------------|----------------|------|
| `scene` | 否 | 第一层只做联网搜索产品彩页。 |
| `tag` | 是 | 标签代表用户进入具体探索方向，可补充语雀链接。 |
| `manual` | 视情况 | 若问题包含课程/产品/使用指南等明确对象，可查；泛泛闲聊不查。 |

`trigger_type` 已确认为 V5 必传字段。后端收到缺失值或非法值时应返回 422，避免首轮场景、标签点击、手动追问的检索策略混淆。

## 5. QAService 接入

建议在 `QAService` 追加 `chat_v5_stream()`，与 `chat_v4_stream()` 平级。

流程：

1. 校验 `CHAT_V5_ENABLED`。
2. 计算 `sid`，确保非空且为 `sess_v5_` 前缀。
3. `ensure_session(session_id=sid, chat_mode="friend_v5", advisor_role="friend")`。
4. 读取最近历史。
5. 保存用户消息。
6. 构造 V5 generator 与 V5 orchestrator。
7. 透传 orchestrator events。
8. 在 `done` 时保存 assistant 完整回答。

注意：

- 已确认 `advisor_role` 可新增 `"friend"`。若落库表结构或历史查询代码存在枚举限制，实施时需要先补充兼容迁移或字段校验测试，不能回退成 V4 的销售语义。
- V5 不应调用 V4 的 memory-only 问答逻辑。
- V5 debug 只在 `EXPOSE_TURN_TRACE` 或新增 `EXPOSE_V5_TRACE` 开启时返回。

## 6. API 路由接入

推荐新建 `app/api/chat_v5_api.py`：

```python
router = APIRouter()

@router.post("/chat/v5/stream")
async def chat_v5_stream(
    request: ChatV5Request,
    qa_service: QAService = Depends(get_qa_service),
) -> StreamingResponse:
    async def event_generator():
        ...
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

错误处理复用 `chat_api.py` 的 `_chat_stream_error_message()` 风格。如果新文件直接 import 私有 helper 不合适，可以将 V5 错误消息写成小型本地 helper，避免重构旧文件。

路由注册有两种方式：

| 方式 | 优点 | 缺点 |
|------|------|------|
| 在 `app/main.py` 追加 `app.include_router(chat_v5_router)` | 最清晰，V5 完全独立 | 需要改已有入口文件 |
| 在 `app/api/chat_api.py` 追加 V5 endpoint | 改动点少，沿用 helper | V5 代码与旧路由混在一起 |

推荐：**独立 router + main 追加注册**。这更符合开闭原则，旧路由文件不继续膨胀。

## 7. 前端联调契约

虽然后端是当前重点，V5 要可验收仍需前端满足：

- V5 模式下生成 `sess_v5_` 前缀 session。
- 场景按钮触发 `POST /chat/v5/stream`，`trigger_type="scene"`。
- 标签点击触发 `POST /chat/v5/stream`，`trigger_type="tag"`。
- 渲染 `done.tags` 为 pill/chip 按钮。
- V5 模式不展示 V4 的试用/演示卡片。
- 不把 V4 历史复用给 V5。

Vite 代理当前已有 `"/chat": "http://127.0.0.1:8000"`，可覆盖 `/chat/v5/stream`，无需新增代理。

## 10. 人工确认项

以下决策已由产品/维护者人工确认，实施时按本节执行：

1. **允许最小接入修改**：可以在已有入口、配置、schema、service 文件中追加 V5 接入代码；仍保持新增为主，不重写 V1/V2/V3/V4。
2. **默认模型固定**：V5 默认模型使用 `qwen3.7-plus`，不调整为 `qwen-plus`。
3. **新增 trigger_type**：V5 后端请求模型新增 `trigger_type`，区分 `scene`、`tag`、`manual`。
4. **强制 session 前缀**：后端校验 V5 `session_id` 必须以 `sess_v5_` 开头。
5. **新增 advisor_role**：V5 使用 `advisor_role="friend"`，与 V4 销售语义隔离。
6. **不做非流式接口**：第一版只实现 `POST /chat/v5/stream`，不提供 `POST /chat/v5`。
7. **返回联网搜索来源**：V5 必须把联网搜索的具体来源内容返回给前端，放入 SSE `done.sources`，`source_type="web"`；语雀补充链接仍使用 `source_type="yuque"`。
