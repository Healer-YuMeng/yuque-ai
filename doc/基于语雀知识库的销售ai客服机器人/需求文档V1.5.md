产品需求文档（PRD）
语雀知识库智能问答系统 V1.5
文档版本：V1.5更新日期：2025 年适用场景：基于语雀 MCP 服务的企业知识库智能问答技术栈（最终修正版）：
- 前端：React + TypeScript + Vite（纯前端 SPA 单页应用）
- 后端：Python + FastAPI
- 核心依赖：语雀MCP/Skill服务
- 核心约束：不使用 RAG 架构，完全基于语雀官方 MCP 服务实现文档检索

---
一、项目概述
1.1 产品定位
基于语雀知识库的智能问答助手，用户输入自然语言问题，系统通过语雀 MCP 服务检索知识库中文本、图片、视频内容，由智能体生成精准回答，为用户提供一站式知识库查询能力。
1.2 现有技术架构
plaintext
用户端 → React+TS+Vite前端 → Python+FastAPI后端 → 语雀MCP/Skill服务 → 语雀知识库
- 前端：React + TypeScript + Vite 负责问答交互、内容展示（文本 / 图片 / 视频），纯客户端渲染
- 后端：Python+FastAPI 负责接口转发、MCP 调用、内容整合、大模型交互
- 核心依赖：语雀 MCP 服务（唯一的文档 / 图片 / 视频检索获取渠道）

---
二、当前现状与核心问题
2.1 现有功能现状
1. 数据源：语雀知识库包含「文本内容 + 图片 + 视频」
2. 问答逻辑：用户提问 → 后端调用语雀 MCP 检索文档 → 智能体基于检索结果回答
3. 内容输出能力
  - 文本：可基于检索到的文档生成回答
  - 图片：智能体支持生成 / 返回语雀中的图片
  - 视频：智能体不支持返回语雀中的视频
4. 用户流程：用户自主输入问题 → 系统被动响应
2.2 核心痛点（优先级从高到低）
1. MCP 检索能力严重受限
  - 问题匹配失败：MCP 未检索到相关文档 → 系统无法给出正确答案
  - 单文档限制：MCP 最多仅能调用1 篇文档 → 无法串联多篇关联文档综合回答
2. 多媒体意图识别缺失
  - 图片 / 视频无意图判断规则：大模型无法判断何时该输出图片、何时该输出视频
3. 视频输出能力缺失
  - 即便 MCP 检索到视频，智能体也无法调用、返回、展示视频

---
三、版本目标（V1.5）
1. 核心目标：突破语雀 MCP 单文档 / 检索失败限制，实现多文档关联整合回答，保证问答覆盖率
2. 基础目标：补全视频输出能力，为图片 / 视频建立意图识别规则，实现多媒体精准输出
3. 兼容目标：不改动现有技术栈、不依赖 RAG、不修改语雀 MCP 原生服务

四、详细功能需求
模块 1：后端 MCP 检索与多文档整合能力（核心）
基于 Python+FastAPI 开发，解决 MCP 检索瓶颈，不改动 MCP 原生接口。
1. 检索增强策略
  - 关键词优化：后端对用户原始问题进行关键词提取 / 同义扩展，提升 MCP 检索命中率
  - 兜底机制：MCP 无检索结果时，返回标准化兜底回答（如：未在语雀知识库中找到相关内容）
2. 多文档串联能力
  - 批量检索：支持通过扩展关键词，调用 MCP 获取多篇相关文档
  - 内容结构化：后端对多篇文档的文本、图片、视频元数据进行清洗、整合
  - 上下文拼接：将多篇文档内容整理为结构化上下文，传递给大模型生成综合回答
3. 接口适配
  - 兼容现有 MCP 接口协议，新增「多文档返回」「多媒体元数据解析」字段
模块 2：智能体 问答与多媒体生成能力
1. 文本问答升级
  - 支持基于多篇语雀文档整合生成回答，而非单一片段
  - 保持回答逻辑连贯、贴合知识库原文
2. 图片输出优化
  - 保留现有图片生成能力，新增意图识别规则
  - 触发条件：用户提问包含「截图、流程图、示意图、界面、步骤图」等关键词时自动输出
3. 视频输出新增
  - 修复视频调用能力：支持通过 MCP 获取语雀视频 URL 并返回给前端
  - 触发条件：用户提问包含「视频、演示、操作教程、讲解、步骤演示」等关键词时自动输出
4. 输出格式规范
5. plaintext
文本回答（整合多文档内容）
🖼️ 相关图片：[图片标题 + 图片预览]
🎥 相关视频：[视频标题 + 可播放视频]
模块 3：多媒体意图识别规则（无 RAG 版）
后端通过 Prompt + 关键词匹配实现，无需额外训练：
1. 图片触发意图用户需要可视化说明、界面展示、流程示意、步骤图解
2. 视频触发意图用户需要操作演示、流程讲解、视频教程、动态展示
3. 优先级规则同时匹配图片 + 视频 → 优先返回视频；无视频则返回图片；均无则仅返回文本
模块 4：前端 React+TS+Vite 展示适配
1. 兼容现有问答交互界面，无需架构重构
2. 新增视频播放器组件，支持直传音雀视频 URL 播放
3. 图片 / 视频统一排版，适配移动端 / PC 端
4. 多文档回答来源标注（可选：展示参考文档标题）

五、非功能需求
1. 兼容性100% 兼容现有 React+TypeScript+Vite 前端、Python+FastAPI 后端、语雀 MCP 服务
2. 性能要求
  - 多文档检索 + 整合耗时 ≤ 2 秒
  - 整体问答响应 ≤ 3 秒
3. 稳定性
  - MCP 检索成功率 ≥ 85%（通过关键词优化提升）
  - 图片 / 视频输出成功率 ≥ 95%
4. 可扩展性支持后续扩展意图关键词、多文档排序规则、兜底话术配置

---
六、技术约束与边界
1. 强制约束
  - 必须使用语雀官方 MCP 作为唯一的文档 / 图片 / 视频获取渠道
  - 禁止接入 RAG、向量数据库、第三方爬虫
  - 不修改语雀知识库原生结构
  - 前端保留现有 React+TS+Vite 架构，不迁移至 Next.js
2. 后端边界仅做：关键词扩展、MCP 接口调用、多文档整合、大模型 Prompt 编排
3. 前端边界仅做：交互、文本 / 图片 / 视频展示，不处理检索逻辑

七、验收标准
验收分类         验收标准
检索能力    用户提问后，MCP 可命中多篇相关文档；无结果时返回兜底话术
文本回答    智能体能串联多篇文档生成完整回答，而非单文档片段
图片输出    触发图片意图 → 自动返回语雀图片，展示正常
视频输出    触发视频意图 → 自动返回语雀视频，前端可播放
意图识别    大模型可精准判断输出文本 / 图片 / 视频
技术兼容    无 RAG、无架构重构，现有服务正常运行
