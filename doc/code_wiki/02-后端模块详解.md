# 02. 后端模块详解

## 1. 后端总体说明

后端核心目录为 `app/`，采用较清晰的分层结构：

- `api`：定义 HTTP 路由
- `service`：业务编排
- `rag`：问答主链路、检索和生成
- `data`：外部数据接入
- `storage`：本地向量索引
- `db`：SQLite 元数据与日志
- `schemas`：接口协议
- `core`：配置与基础能力

## 2. 应用入口

### 2.1 `app/main.py`

职责：

- 创建 FastAPI 应用
- 在生命周期中初始化 `QAService`
- 组装 `YuqueLoader`、`VectorStore`、`DocumentRepository`、`QALogRepository`
- 挂载聊天路由
- 根据 `frontend/dist` 是否存在决定托管 React 产物还是 `web/` 回退页

关键点：

- `lifespan()` 统一完成启动与关闭
- `application.state.qa_service` 作为 API 层共享依赖
- `/assets` 静态资源路径由后端直接托管

## 3. API 层

### 3.1 `app/api/chat_api.py`

这是后端所有主要 HTTP 接口的集中路由文件。

#### 主要接口

| 接口 | 方法 | 作用 |
|---|---|---|
| `/health` | GET | 健康检查 |
| `/runtime-mode` | GET | 返回当前运行模式 |
| `/mcp/capabilities` | GET | 返回 MCP 接入与工具能力 |
| `/chat` | POST | 非流式问答 |
| `/chat/stream` | POST | 流式问答，返回 SSE |
| `/index/rebuild` | POST | 重建向量索引 |
| `/sync/yuque` | POST | 以另一默认查询同步语雀文档 |
| `/docs/toc` | GET | 返回知识库目录树 |
| `/docs/suggest` | POST | 返回文档联想与候选项 |
| `/yuque/asset` | GET | 同源代理语雀图片资源 |

#### 关键函数说明

| 函数 | 作用 |
|---|---|
| `_ensure_yuque_token_for_profile()` | 校验主账号或副账号 Token 是否可用 |
| `chat()` | 调用 `QAService.chat()`，返回一次性问答结果 |
| `chat_stream()` | 调用 `QAService.chat_stream()`，封装为 SSE |
| `mcp_capabilities()` | 汇总 MCP 工具能力、账号 login 与作用域 |
| `docs_toc()` | 拉取语雀目录树，用于前端左侧知识库面板 |
| `docs_suggest()` | 用于输入框 `@文档` 联想 |
| `yuque_asset_proxy()` | 通过白名单代理语雀 CDN 图片，解决前端同源展示 |

#### 设计特点

- 路由层只负责协议转换与错误映射，不承载核心业务逻辑
- 对流式场景统一输出 `event: stage/token/done/error`
- 对大模型连接错误、限流、503 等做了用户可读的错误信息翻译

## 4. 服务层

### 4.1 `app/service/qa_service.py`

`QAService` 是后端的总编排服务，也是最重要的业务枢纽。

#### 主要职责

- 初始化并持有 `YuqueLoader`、`VectorStore`、仓储、切片器、Embedder、Generator、MCP Client
- 构建默认 `RAGPipeline`
- 对外提供同步与流式问答能力
- 根据模型、owner、token_profile 动态构建运行时 pipeline
- 执行索引重建
- 记录问答日志

#### 核心方法

| 方法 | 作用 |
|---|---|
| `startup()` | 初始化数据库表 |
| `shutdown()` | 关闭语雀客户端 |
| `chat()` | 非流式问答总入口 |
| `chat_stream()` | 流式问答总入口 |
| `runtime_mode()` | 返回 `rag` 或 `direct_yuque` |
| `mcp_capabilities()` | 汇总 MCP 可用工具与接入状态 |
| `resolve_yuque_token_logins()` | 读取主/副账号对应的语雀 login |
| `rebuild_index()` | 拉文档、切片、向量化并重建索引 |

#### 动态路由逻辑

`QAService` 并不总是使用同一个固定 `RAGPipeline`。当请求中指定了以下变量时，它会临时构造一套新的检索环境：

- `model`：按前端模型选择使用 `DeepSeekGenerator` 或 `OpenAIGenerator`
- `owner`：改写语雀作用域
- `token_profile`：切换主账号或副账号 Token
- `selected_yuque_docs`：将用户在前端显式选择的文档作为检索锚点

这部分逻辑由 `_run_one()` 和 `_run_one_stream()` 实现。

#### 关键辅助函数

| 函数 | 作用 |
|---|---|
| `_doc_anchor_pairs()` | 将前端所选文档转成 `(doc_id, slug)` 锚点 |
| `_retrieving_stage_detail()` | 生成流式阶段文案 |
| `_generating_stage_detail()` | 根据检索模式生成更准确的“正在生成”提示 |
| `_embedder_for_profile()` | 避免副账号或非默认 scope 误用主索引向量空间 |
| `_build_generator_by_selected_model()` | 根据模型前缀决定走 OpenAI 还是 DeepSeek |

#### 设计亮点

- 把“索引空间是否与当前语雀作用域一致”的判断放到服务层，避免错召回
- 流式模式下显式拆分为检索、识图、生成三个阶段，便于前端展示进度
- 对文档锚定、模型切换、副账号访问都做了统一收敛

## 5. RAG 编排层

### 5.1 `app/rag/pipeline.py`

`RAGPipeline` 负责“拿到问题后该如何完成一次回答”。

#### 主要职责

- 检查生成器是否可用
- 判断是否应直接走“助手能力说明”而跳过常规检索
- 调用 `Retriever` 完成上下文召回
- 对检索结果执行 `scope_help` 纠偏
- 对命中文档执行插图增强
- 调用 `Generator` 生成或流式生成答案
- 合并调试信息

#### 核心方法

| 方法 | 作用 |
|---|---|
| `retrieve_context()` | 先检索上下文，再做 scope_help 与插图增强 |
| `stream_answer_tokens()` | 以 token 流的方式生成答案 |
| `run()` | 标准非流式问答 |
| `run_stream()` | 返回检索结果、调试信息与 token 迭代器 |

#### 关键设计

- `retrieve_context()` 与 `stream_answer_tokens()` 拆开后，流式接口可以在首 token 前先发出阶段事件
- `debug` 信息不是简单日志，而是结构化返回给前端，用于解释实际检索路径

## 6. 检索层

### 6.1 `app/rag/retriever.py`

`Retriever` 是整个系统最复杂的模块，负责决定“从哪里检索、检索什么、什么情况下回退”。

#### 核心输入

- `question`
- `skill_id`
- `doc_anchors`
- 当前是否存在 `Embedder`
- 当前是否启用 `YuqueMCPClient`

#### `RetrievalResult`

统一检索输出结构：

- `contexts`：供大模型使用的上下文文本列表
- `sources`：展示给用户的来源列表
- `fallback_used`：是否走了回退链路
- `debug`：检索路径、工具与统计信息

#### 主检索策略

1. 若 `skill_id == stale-detector`，走专门的过期检测检索
2. 若当前没有 embedding，进入 `direct_yuque` 模式
3. 若有 embedding，先查询 `VectorStore`
4. 若用户选中了文档，优先使用文档锚点
5. 若强召回不足，则回退到 MCP
6. 若 MCP 也无结果，则返回空上下文或弱命中结果

#### 主要内部方法

| 方法 | 作用 |
|---|---|
| `retrieve()` | 检索主入口 |
| `_retrieve_stale_detector_context()` | 基于 `updated_at` 构造过期候选上下文 |
| `_retrieve_from_doc_anchors()` | 根据用户显式选择的文档拉取正文 |
| `_retrieve_from_yuque()` | 在 direct 模式下使用语雀搜索与正文拉取 |
| `_retrieve_doc_list_context()` | 处理“有哪些文档”类问题 |
| `_retrieve_directory_context()` | 处理“目录/结构/大纲”类问题 |
| `_retrieve_from_docs_title_match()` | 标题匹配回退 |
| `_retrieve_from_toc_titles()` | TOC 标题匹配回退 |
| `_retrieve_from_mcp_or_empty()` | 统一的 MCP 回退入口 |
| `_try_auto_mcp_tool_route()` | 通过 LLM 自动决定 MCP 应调哪个只读工具 |
| `_classify_intent()` | 将问题分类为 `directory/doc_list/content` |

#### 检索策略细节

##### A. 向量模式

- 使用 `Embedder.embed_query()` 生成问题向量
- 通过 `VectorStore.search()` 获取 top-k 片段
- 若分数达到阈值，直接返回向量检索结果
- 若分数不足，则尝试 `YuqueMCPClient.search()`

##### B. 直连语雀模式

- 先做意图分类
- 目录类问题优先获取 TOC
- 文档列表类问题优先获取 `list_docs`
- 内容类问题使用 `search_docs()` + `get_doc()`
- 若 OpenAPI 没命中，再走标题匹配和 MCP 回退

##### C. MCP 回退模式

MCP 回退并不只是“再搜一次”，而是有多个分支：

- `combined_inventory`：组合 `yuque_list_docs` + `yuque_get_toc`
- `toc`：目录树回答
- `list_docs`：文档列表回答
- `search`：搜索后再 `get_doc`
- `title_fallback`：按标题匹配再拉正文
- `auto_router`：由 LLM 自动选择 MCP 工具

#### 检索层的业务特性

- 能识别“目录问题”和“正文问题”是不同检索任务
- 能识别“图片统计类问题”和“想看文档插图内容”的差异
- 能把前端选中的 `@文档` 作为强约束条件
- 能把检索路径完整写入 `debug`，便于追查回答为何来自某条来源

## 7. 生成层

### 7.1 `app/rag/generator.py`

生成层抽象为 `Generator` 接口，当前实现包括：

- `DeepSeekGenerator`
- `OpenAIGenerator`

其中 `OpenAIGenerator` 直接继承 `DeepSeekGenerator`，两者共享同一套 prompt 结构，只是底层 API key 与 base URL 不同。

#### 主要职责

- 生成系统提示词与用户 prompt
- 约束输出必须为中文 Markdown
- 将上下文和来源编号注入 prompt
- 支持完整生成与流式生成

#### 关键方法

| 方法 | 作用 |
|---|---|
| `_system_message()` | 根据上下文类型动态调整系统提示 |
| `_build_prompt()` | 组装用户问题、上下文和来源 |
| `generate()` | 非流式生成 |
| `stream_generate()` | 流式生成 |

#### 特殊处理

当上下文里出现以下特殊块时，生成器会增强约束：

- `【合并知识库清单`：要求答案先输出目录树，再输出统计表
- `【文档插图`：要求原样使用图片 Markdown 链接，不改写代理 URL

## 8. 数据接入层

### 8.1 `app/data/yuque_loader.py`

`YuqueLoader` 是语雀 OpenAPI 的轻量封装。

#### 主要能力

- `search_docs()`：按关键词检索语雀文档
- `get_doc()`：拉取文档正文
- `fetch_documents_for_bootstrap()`：索引构建时获取文档全集合
- `get_book_toc()`：获取知识库目录树
- `fetch_self_login()`：读取当前 Token 对应 login
- `list_docs()`：列出知识库文档元信息

#### 数据结构

- `YuqueDocument`
- `YuqueSearchHit`
- `YuqueTocNode`
- `YuqueDocMeta`

#### 设计特点

- 对 Token 缺失、HTTP 错误、非法 JSON 统一抛出 `YuqueLoaderError`
- 自动标准化语雀 URL
- `scope` 以 `login/repo` 形式贯穿整个请求过程

### 8.2 `app/data/mcp_client.py`

`YuqueMCPClient` 是对 `yuque-mcp-server` 的只读适配层。

#### 支持能力

- 搜索：`search()`
- 拉文档正文：`get_doc()`
- 列文档：`list_docs()`
- 取目录：`get_toc()`
- 读取账号、知识库、小记：`get_user()`、`list_books()`、`get_book()`、`list_notes()`、`get_note()`

#### 特点

- 只允许调用白名单内的只读工具
- 对返回 JSON、文本、列表结构都做了解析兼容
- 把 MCP 数据标准化为 `MCPSearchResult`、`MCPDocMeta`、`MCPTocNode`

## 9. 存储层

### 9.1 `app/storage/vector_store.py`

`VectorStore` 负责本地向量索引的持久化与检索。

#### 主要职责

- 管理 `index.faiss`、`index.npy`、`chunks.json`
- 支持向量重建 `rebuild()`
- 支持相似度搜索 `search()`
- 在没有 `faiss` 时退化为 NumPy 余弦相似度

#### 数据结构

- `StoredChunk`：持久化后的切片
- `RetrievedChunk`：检索命中结果，带分数

#### 特点

- 向量写入前统一归一化
- 优先使用 FAISS，缺失时自动退化到 NumPy
- 元信息独立保存在 `chunks.json` 中，便于调试

## 10. 数据库层

### 10.1 `app/db/models.py`

定义三张核心表：

| 表名 | 用途 |
|---|---|
| `documents` | 存储文档级元信息 |
| `chunks` | 存储切片级摘要信息 |
| `qa_logs` | 记录问答日志 |

### 10.2 `app/db/repositories.py`

#### `DocumentRepository`

- `init_db()`：初始化表结构
- `replace_documents()`：重建索引后重写 `documents` 与 `chunks`

#### `QALogRepository`

- `log_chat()`：把问题、答案、来源与 fallback 状态写入 `qa_logs`

### 10.3 `app/db/session.py`

`DatabaseSessionFactory` 负责返回 `aiosqlite` 连接，是 SQLite 的最小连接工厂。

## 11. 协议层

### 11.1 `app/schemas/chat.py`

定义了聊天接口的核心协议：

- `ChatRequest`
- `ChatResponse`
- `SourceItem`
- `SelectedYuqueDocRef`
- `RuntimeModeResponse`
- `MCPCapabilitiesResponse`

其中 `selected_yuque_docs` 是前后端协作的重要字段，用于将用户前端所选文档带入检索层。

### 11.2 `app/schemas/docs.py`

定义目录和联想用协议：

- `DocSuggestRequest`
- `DocMeta`
- `DocSuggestResponse`

`DocMeta` 同时兼顾文档联想和 TOC 树节点展示，因此包含 `toc_level`、`toc_kind`、`toc_selectable` 等目录属性。

## 12. 基础设施层

### 12.1 `app/core/config.py`

`Settings` 集中管理所有环境变量与路径配置，包括：

- 应用基础配置
- 语雀 Token 与 scope
- embedding / LLM / vision 配置
- MCP 命令与工具名
- 前端静态目录
- 文档插图与多模态开关

### 12.2 其他核心基础设施

- `app/core/logger.py`：日志初始化与获取
- `app/core/yuque_credentials.py`：主/副 Token 与作用域归一逻辑

## 13. 后端维护建议

- 新增 API 时，路由层保持薄，业务尽量放到 `QAService` 或独立 service
- 新增检索模式时，优先扩展 `Retriever`，并保持 `RetrievalResult` 兼容
- 新增模型供应商时，先扩展 `Generator` 抽象，再在 `QAService` 中接入
- 涉及语雀新接口时，优先封装到 `YuqueLoader` 或 `YuqueMCPClient`，避免散落在业务层
