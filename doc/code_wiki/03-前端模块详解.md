# 03. 前端模块详解

## 1. 前端概览

前端位于 `frontend/`，采用 `React 19 + TypeScript + Vite`。当前前端并不是一个多页面应用，而是一个围绕聊天问答场景构建的单页应用，绝大多数交互逻辑集中在 `frontend/src/App.tsx`。

## 2. 目录结构

```text
frontend/
  src/
    App.tsx
    main.tsx
    App.css
    index.css
    markdownAutolink.ts
    matchRoutedSkill.ts
  public/
  package.json
  vite.config.ts
```

## 3. 构建与运行

### 3.1 `package.json`

前端提供以下核心脚本：

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动 Vite 开发服务器 |
| `npm run build` | TypeScript 构建并产出 `dist` |
| `npm run lint` | 执行 ESLint |
| `npm run preview` | 预览构建产物 |

### 3.2 `vite.config.ts`

Vite 代理了以下后端路径到 `http://127.0.0.1:8000`：

- `/chat`
- `/mcp`
- `/docs`
- `/yuque`

这意味着开发模式下前端默认与本机 FastAPI 配合联调，避免浏览器跨域问题。

## 4. 入口文件

### 4.1 `frontend/src/main.tsx`

职责非常单一：

- 挂载 React 根组件
- 引入全局样式
- 渲染 `<App />`

## 5. 页面主容器

### 5.1 `frontend/src/App.tsx`

`App.tsx` 是当前前端的状态中心、交互中心和主页面容器。可以把它理解为一个“大型页面控制器”。

#### 主要职责

- 管理多会话历史与本地存储
- 管理消息列表与流式回答状态
- 调用 `/chat/stream` 消费 SSE
- 调用 `/docs/toc` 和 `/docs/suggest` 实现知识库面板与 `@文档` 联想
- 展示 MCP 工具能力
- 展示 Skill 快捷入口与提示
- 管理“选择文档后再提问”的文档锚定流程

## 6. 核心状态模型

### 6.1 消息与会话

主要类型包括：

- `ChatItem`：单条消息，包含角色、正文、调试信息、流式阶段与来源链接
- `SessionState`：单个会话，包含标题、更新时间、消息数组与置顶状态
- `SourceLinkItem`：后端回答返回的来源链接

这套设计让前端不仅能渲染最终答案，还能展示：

- 当前检索阶段
- 生成耗时
- 调试信息
- 最终引用来源

### 6.2 文档与技能

前端还定义了以下重要类型：

- `DocMeta`：目录与联想统一使用的文档模型
- `SelectedYuqueDocLocal`：当前已选择的文档锚点
- `SkillDef`：每个内置技能的说明、触发词和快捷提问模板

## 7. 关键函数说明

### 7.1 流式相关

| 函数 | 作用 |
|---|---|
| `readStreamChunkWithIdle()` | 为读取 `ReadableStream` 增加空闲超时保护 |
| `parseSseEvent()` | 将 SSE 块解析成 `{ event, data }` |
| `formatStreamStageLine()` | 把后端 `stage` 事件转成可显示的阶段文本 |
| `parseDoneSourceLinks()` | 从 `done` 事件中提取参考来源 |
| `stopStreaming()` | 用户手动终止当前流式请求 |
| `askQuestion()` | 问答主入口，负责发起 `/chat/stream`、消费 SSE 并更新界面 |

#### `askQuestion()` 的工作过程

1. 校验输入是否为空、是否正在流式生成
2. 根据问题文本判断是否会触发某个 Skill
3. 若该 Skill 需要先选文档，则阻止发送并提示用户
4. 将问题与已选文档组装成请求体
5. 向 `/chat/stream` 发起请求
6. 解析后端返回的 `stage/token/done/error`
7. 增量更新当前助手消息
8. 在结束时保存来源、调试信息和最终答案

#### 前端对流式异常的处理

`askQuestion()` 对以下异常场景做了细分：

- 连接超时
- 长时间无数据的空闲超时
- 用户主动停止
- 服务端无有效流响应
- 通用错误回退

这让用户能区分“模型慢”“服务不可用”“手动停止”这些不同问题。

### 7.2 文档联想与知识库面板

| 函数 | 作用 |
|---|---|
| `loadKbToc()` | 加载知识库目录树 |
| `handleQuestionChange()` | 监听输入框变化并触发 `@文档` 联想 |
| `extractAtToken()` | 从光标位置提取当前 `@` 词段 |
| `applyDocSuggestPick()` | 将联想结果插入输入框并加入已选文档 |
| `pickDocFromKbPanel()` | 从知识库面板中选择文档 |
| `removeSelectedYuqueDoc()` | 取消某个已选文档 |
| `updateDocFloatRect()` | 计算联想浮层和知识库浮层位置 |

#### 交互特点

- 输入框中键入 `@` 会触发 `/docs/suggest`
- 左侧知识库面板会调用 `/docs/toc`
- 文档被选中后，不只是显示在 UI 中，还会在请求里进入 `selected_yuque_docs`
- 后端随后会把这些文档作为检索锚点优先处理

### 7.3 会话管理

| 函数 | 作用 |
|---|---|
| `createSession()` | 创建新会话 |
| `togglePinSession()` | 置顶或取消置顶 |
| `renameSession()` | 重命名会话 |
| `removeSession()` | 删除会话 |
| `shareSession()` | 使用 Web Share 或复制文本 |
| `touchSession()` | 更新会话时间戳，保证排序正确 |
| `readStoredSessionState()` | 从 `localStorage` 恢复历史会话 |

#### 会话设计特点

- 历史会话保存在本地，不走后端持久化
- 会话支持置顶、重命名、删除
- 允许快捷键创建新会话
- 排序时优先按 `pinned`，其次按更新时间

### 7.4 Skill 快捷能力

| 函数 | 作用 |
|---|---|
| `applyQuickSkillShortcut()` | 点击 Skill 快捷项后自动填入问题模板 |
| `buildSkillQuickBody()` | 生成带文档标题上下文的快捷提问文本 |

前端内置多种 Skill 定义，例如：

- `reading-digest`
- `daily-capture`
- `note-refine`
- `knowledge-connect`
- `style-extract`
- `smart-search`
- `smart-summary`
- `stale-detector`

每个 Skill 包含：

- 展示名
- 描述
- 触发关键词
- 是否必须先选择文档
- 快捷提问模板

## 8. 前后端协作点

### 8.1 `matchRoutedSkill.ts`

这个文件的作用是让前端和后端共享同一套 Skill 触发规则。

职责：

- 根据用户输入判断本轮会命中的 `skill_id`
- 与后端 `app/rag/skill_router.py` 保持关键词和判定顺序一致

意义：

- 前端可以提前给用户展示“将触发什么能力”
- 某些必须选文档的能力可以在前端直接做拦截，减少无效请求

### 8.2 `markdownAutolink.ts`

职责：

- 对裸露 URL 做预处理，包裹为 `<https://...>`
- 避免中文标点、全角括号等把链接边界识别错

意义：

- 回答里经常会混入 URL、语雀链接、Markdown 内容
- 这个工具函数能提升 `react-markdown` 渲染稳定性

## 9. 页面组成概念

虽然 `App.tsx` 当前是单文件实现，但从逻辑上可分为几个区域：

1. 侧栏：历史会话、账户信息、MCP 能力、技能说明
2. 聊天区：消息渲染、调试信息、来源展示
3. 输入区：问题编辑、发送、停止、文档锚定
4. 悬浮层：`@文档` 联想与知识库目录面板

## 10. 当前前端设计特点

- 以流式聊天体验为中心，而不是传统表单页
- 非常依赖后端返回的 `stage` 和 `debug` 信息
- 本地状态较多，`App.tsx` 已经承担了页面、状态与请求的多重职责
- 为了适配知识库问答，特意增加了“文档锚定”与“知识库目录浏览”能力

## 11. 风险与后续重构建议

### 11.1 当前风险

- `App.tsx` 文件体量很大，维护成本持续升高
- UI 状态、网络请求和业务规则高度耦合
- 文档联想、SSE 处理、会话管理都在同一文件中，测试与复用不便

### 11.2 建议拆分方向

- `components/`：拆出消息列表、会话侧栏、输入框、知识库面板
- `hooks/`：拆出 `useChatStream`、`useDocSuggest`、`useSessions`
- `types/`：统一收拢前端类型定义
- `api/`：封装 `/chat`、`/docs`、`/mcp` 请求函数

## 12. 维护建议

- 修改 Skill 触发词时，必须同步检查后端 `skill_router`
- 修改 SSE 协议时，前后端要一起调整 `stage/token/done/error` 事件结构
- 修改 `DocMeta` 或 `selected_yuque_docs` 时，要同时核对后端 schema 和检索锚定逻辑
- 如果继续增强前端功能，应优先做组件化和 Hook 化拆分
