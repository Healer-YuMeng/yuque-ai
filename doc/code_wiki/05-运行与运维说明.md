# 05. 运行与运维说明

## 1. 目标

本文用于说明项目如何准备环境、启动前后端、构建索引、执行测试以及理解运行时模式。

## 2. 环境准备

在仓库根目录执行：

```bash
source scripts/activate.sh
python -m pip install -r requirements.txt
cp .env.example .env
```

前端首次安装依赖：

```bash
cd frontend
npm install
```

## 3. 核心环境变量

### 3.1 最低必需配置

| 变量 | 说明 |
|---|---|
| `YUQUE_TOKEN` | 语雀访问 Token |
| `YUQUE_SCOPE` | 默认知识库作用域，通常是 `login/repo` |
| `DEEPSEEK_API_KEY` 或 `LLM_API_KEY` | 文本生成模型 API key |

### 3.2 向量检索相关

| 变量 | 说明 |
|---|---|
| `EMBEDDING_API_KEY` | embedding API key |
| `EMBEDDING_BASE_URL` | embedding 服务地址 |
| `EMBEDDING_MODEL` | embedding 模型名 |

### 3.3 模型相关

| 变量 | 说明 |
|---|---|
| `LLM_MODEL` | 默认大模型 |
| `LLM_BASE_URL` | 默认 LLM 基础地址 |
| `OPENAI_API_KEY` | `gpt-*` 模型使用 |
| `DEEPSEEK_API_KEY` | `deepseek-*` 模型使用 |

### 3.4 MCP 相关

| 变量 | 说明 |
|---|---|
| `YUQUE_MCP_COMMAND` | MCP 服务命令 |
| `YUQUE_MCP_ARGS` | MCP 启动参数 |
| `YUQUE_MCP_SEARCH_TOOL` | 搜索工具名 |
| `YUQUE_MCP_GET_DOC_TOOL` | 拉正文工具名 |

### 3.5 其它可选能力

| 变量 | 说明 |
|---|---|
| `YUQUE_TOKEN_SECONDARY` | 副账号 Token |
| `YUQUE_SCOPE_SECONDARY` | 副账号作用域 |
| `VISION_ENABLED` | 是否启用视觉识图 |
| `VISION_MODEL` | 视觉模型 |
| `EXPOSE_SOURCE_URLS` | 是否对前端返回真实来源 URL |

## 4. 启动方式

### 4.1 方式一：一键联调

```bash
make dev
```

等价于：

```bash
./scripts/dev_up.sh
```

默认地址：

- 后端：`http://127.0.0.1:8000`
- 前端：`http://127.0.0.1:5173`

### 4.2 方式二：分别启动前后端

后端：

```bash
make run
```

或：

```bash
source scripts/activate.sh
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

前端：

```bash
cd frontend
npm run dev
```

### 4.3 方式三：构建前端后由 FastAPI 托管

```bash
make build-ui
make run
```

此时只需要访问：

```text
http://127.0.0.1:8000/
```

## 5. 索引构建

### 5.1 使用脚本构建

```bash
python scripts/build_index.py
```

可选指定 bootstrap 查询词：

```bash
BOOTSTRAP_QUERY=退款 python scripts/build_index.py
```

### 5.2 使用 API 重建

可调用以下接口：

- `POST /index/rebuild`
- `POST /sync/yuque`

区别在于默认使用的 bootstrap 查询词不同。

### 5.3 索引构建内部过程

1. 调语雀搜索文档
2. 拉取正文
3. 文本切片
4. 生成 embedding
5. 写入向量索引
6. 将文档和切片摘要写入 SQLite

| 命令 | 说明 |

## 7. 运行时模式说明

### 7.1 `rag` 模式

触发条件：

- 已配置 embedding key
- 当前问题所用 scope 与本地索引 scope 一致
- 当前使用的是主账号向量空间

特点：

- 先向量检索
- 命中弱时可回退到 MCP
- 适合默认知识库下的常规问答

### 7.2 `direct_yuque` 模式

触发条件：

- 未配置 embedding
- 当前切换到非默认 scope
- 使用副账号 Token

特点：

- 不使用本地向量库
- 主要依赖语雀 OpenAPI 与 MCP
- 更适合动态切 scope 或无向量环境

## 8. 运行时数据

### 8.1 SQLite

默认数据库位置：

```text
data_runtime/rag_mvp.db
```

主要保存：

- 文档元信息
- 切片摘要
- 问答日志

### 8.2 向量索引

默认目录：

```text
data_runtime/vector_store/
```

可能出现的文件：

- `index.faiss`
- `index.npy`
- `chunks.json`

## 9. 接口速查

| 接口 | 用途 |
|---|---|
| `GET /` | 打开前端页面 |
| `GET /health` | 健康检查 |
| `GET /runtime-mode` | 查看当前运行模式 |
| `GET /mcp/capabilities` | 查看 MCP 工具和账号信息 |
| `POST /chat` | 非流式问答 |
| `POST /chat/stream` | 流式问答 |
| `GET /docs/toc` | 加载知识库目录 |
| `POST /docs/suggest` | 文档联想 |
| `POST /index/rebuild` | 重建索引 |
| `POST /sync/yuque` | 重新同步语雀文档 |
| `GET /yuque/asset` | 语雀图片代理 |

## 10. 测试

项目测试位于 `tests/`，覆盖范围主要包括：

- API schema 与接口行为
- 检索路由与回退逻辑
- MCP 能力接线
- 文档 TOC 与联想
- 语雀接入与图片处理

执行命令：

```bash
pytest
```

或：

```bash
make test
```

## 11. 常见问题

### 11.1 启动后只能看到旧页面

原因通常是：

- `frontend/dist` 不存在
- 因而 FastAPI 自动回退到 `web/`

解决方式：

```bash
make build-ui
make run
```

### 11.2 问答能启动但没有回答

优先检查：

- 是否配置了 `DEEPSEEK_API_KEY`、`LLM_API_KEY` 或 `OPENAI_API_KEY`
- 模型名与 key 是否匹配
- `LLM_BASE_URL` 或 `DEEPSEEK_BASE_URL` 是否可访问

### 11.3 回答不走向量检索

优先检查：

- 是否配置 `EMBEDDING_API_KEY`
- 当前请求的 `owner/scope` 是否与默认索引一致
- 是否使用了副账号 Token

### 11.4 联调脚本中的 npm 路径异常

`scripts/dev_up.sh` 与 `scripts/build_frontend.sh` 当前写死了：

```text
/opt/homebrew/bin/npm
```

如果你的环境不在这个路径，可直接手工在 `frontend/` 下执行：

```bash
npm install
npm run dev
```

或修改脚本中的 npm 路径。

## 12. 运维与排障建议

- 出现检索异常时，优先查看后端日志中的 `retrieval_mode`、`mcp_route`
- 出现问答不稳定时，查看前端消息中的 `debug` 字段
- 出现命中文档不准时，检查是否应该使用 `@文档` 做锚定
- 出现图片无法展示时，检查 `/yuque/asset` 与图片白名单逻辑
- 修改 `.env` 后，通常需要重启后端服务使配置重新加载

## 13. 演进建议

- 若后续进入生产环境，建议为前后端构建更稳定的 Node 与 Python 环境管理
- 现有启动脚本更偏本地开发，部署时建议抽出更标准的进程管理方案
- 如果索引规模继续增长，建议引入增量索引与文档版本检测，而不是每次全量重建
